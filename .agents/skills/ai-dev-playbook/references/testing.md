# 测试纪律：红绿证是信仰

测试的全部价值在于**它失败的时候**。一套从不失败的测试只是代码的复读机。本文件的每条纪律都在防一种"假绿"。

## 一、TDD 红绿证三步

1. **红**：先写测试并运行，必须看到失败——且失败原因必须是"功能未实现"，不是语法错/导入错；
2. **绿**：最小实现让测试通过——"最小"指不多写任何被测试没要求的行为；
3. **重构**：绿之后才允许整理结构，全程保持绿。

**停止信号：测试没经过红直接绿 = 停下来**。要么测试没测到新行为（在测既有实现），要么测试写错了——两种情况这个测试都是废物。

**修复已合入代码时证红的技巧**：用 `git worktree` 检出修复前的 commit 跑新测试拿红，**禁止在主树注释掉修复"反向证红"**——忘恢复就是事故。

## 二、断言精确：禁 `A or B`

```python
# 禁：状态码/关键字段用宽松断言
assert resp.status in (200, 404)      # 这行会把 404 的 bug 洗成绿
# 对：精确断言
assert resp.status_code == 200
assert body["data"]["items"][0]["title"] == "预期标题"
```

**为什么**：`A or B` 断言等于没有断言——它把两条路径都算通过，测试的失败信号被稀释到无。

## 三、写库必读回

写库测试必须 SELECT 读回验证落库内容，**禁止只看执行不报错**。`INSERT` 成功≠写对了（字段错位/默认值覆盖/编码问题只有读回能抓到）。迁移测试同理：upgrade → downgrade -1 → upgrade 全程走通。

## 四、守账测试

会漂移的业务数字（端点总数、默认阈值、文案标记行）由守账测试锁定：

```python
def test_api_contract():
    assert len(routes) == 66  # api.md 头部标记行与此对账；新增/删除端点未同步即红
```

数字漂移从"评审靠眼"变成"CI 必红"。

## 五、复现测试永久保留

bug 修复先写复现测试再修，**修复后该测试永久保留**——它是"此 bug 曾存在"的活档案，回归时第一个报警。📌 实例：`test_docx_dangling_style.py`（docx style=None 解析缺陷）修复后留档，后续 parser 改动若有回归第一时间红。

## 六、测试分层与性价比

| 层 | 范围 | 门禁 |
|----|------|------|
| unit | 纯函数/服务逻辑（Stub 全套） | 增量必跑 |
| api | 端点契约（鉴权/参数/错误码） | 增量必跑 |
| integration | 真 DB + Stub 外部依赖 | 里程碑/怀疑波及时 |
| E2E-L1 | stub 全链零外部依赖，断言**通道+结构** | 每 MR |
| E2E-L2 | 真实依赖（部署机），断言**语义** | 显式开启 |

**L1/L2 分层的关键认知**：stub 环境下语义不可断言（stub 的回答是剧本），只断"链路通、结构对"——把语义验证留给 L2，是测试性价比的显式设计，不是偷懒。

**覆盖率门禁**：核心层（业务逻辑目录）设 `--cov-fail-under` 下限进 CI；日常只跑增量相关测试，全量留给里程碑收口。

## 七、测试环境纪律（实战教训浓缩）

- **测试夹具数据要过一遍产品的校验/扫描逻辑**：📌 实例——E2E 夹具流水号是 17 位纯数字串，被银行卡敏感扫描以约 1/10 概率误命中（过 Luhn），文档被判"待确认"导致 setup 随机挂。夹具生成后应主动验证：不触发敏感扫描、不撞查重、格式断言可满足。
- **门禁与资源密集长跑严禁并行**：📌 实例——8G 机器上 vitest 与评测跑分并行 → 容器被 OOM 杀（exit 137）；浏览器自动化与 TEI/MinerU 容器并存 → 内存耗尽浏览器被杀。跑重型验证前盘点内存/CPU 占用。
- **外部服务做对应隔离**：不需要真服务的测试环境要把依赖指到不可达/降级路径（📌 实例：e2e 栈清空 MINERU_BASE_URL 走 pypdf 降级，避免真实 OCR 数百秒拖垮解析线程池）。
- **Stub 注入走依赖缝**：测试经 monkeypatch/依赖注入换 Stub，禁止改产品代码加测试分支。
