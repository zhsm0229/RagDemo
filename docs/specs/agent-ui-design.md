## 1. 页面定位、菜单与路由

### 1.1 菜单命名与位置（MainLayout 分组对齐）

| 页面 | 菜单名 | 分组与位置 | 可见性 | 理由 |
|------|--------|-----------|--------|------|
| MemoryView | **我的记忆** | 无标题主组，`智能问答` 之后、`帮助` 之前 | 全员（member + admin） | 记忆是**个人数据**，与"智能问答"同属员工日常动线；不放"知识库/管理"两组（那是管理员运营域） |
| TemplateGenView | **模板生成** | "知识库"组，`问答对管理` 之后 | 仅 admin | 产物是问答对草稿，流向"问答对管理"审核；紧邻形成"生成 → 审核"动线（权限口径与 kb 组一致） |

菜单命名"我的记忆"取自员工视角第一人称（对齐手册话术"你的记忆"）；不建议"记忆管理"（管理员口吻）或"个性化设置"（语义过宽）。"模板生成"沿用任务命名；若评审认为指向不明，备选名"问答对生成"（变更需同步手册与帮助，见文首上线义务）。

### 1.2 路由（`frontend/src/router/index.ts`）

```
/memory          name=memory          meta.title=我的记忆                    （不设 requiresAdmin）
/kb/template-gen name=kb-template-gen meta.title=知识库·模板生成  requiresAdmin=true
```

两页均为 MainLayout 子路由；页面标题经 `route.meta.title` 呈现在顶栏（现有机制，不新增头组件）。

## 2. 我的记忆（MemoryView）

### 2.1 页面结构（自上而下三段）

```
┌─ 我的记忆 ─────────────────────────────────────────────────────┐
│ 记忆功能 [switch]  开启后，回答会参考你的记忆；关闭后立即退出参考，  │
│                    已有记忆保留、不自动删除。                      │
│ [记忆内容关键字____] [查询] [重置]        [记忆输入____(≤200字)] [添加] │
│──────────────────────────────────────────────────────────────│
│ 内容                                  来源    添加时间          操作 │
│ 我负责华东区客服，回复时请用中文        [手动]  2026-10-06 10:24  删除 │
│ 倾向先给结论再给依据                   [自动]  2026-10-06 09:02  删除 │
│──────────────────────────────────────────────────────────────│
│                              共 2 条  < 1 >  20/页▾              │
└──────────────────────────────────────────────────────────────┘
```

1. **开关置顶行**：页面最高优先级控制（功能总闸），独立一行置于筛选/工具栏之上；行内为 `记忆功能` 文字 + el-switch + 一句常驻说明（不折叠、不放 tooltip——总闸语义必须首屏可读）。
2. **工具栏行**：左侧筛选（内容关键字 + 查询/重置，对齐 ui-spec §22.1 同行口径、变更即查回第 1 页）；右侧手动添加（输入框 + `添加` 按钮，见 §2.3）。
3. **列表区**：el-table（border + stripe，v-loading），列与信息密度见 §2.4；分页右下。

### 2.2 开关行语义

- 开关状态来自记忆设置接口；加载完成前 switch 置 `disabled`，避免先渲染默认值再跳变（对齐"禁止展示旧数据"红线）。
- 切换即保存（对齐 QaPairsView 启停范式）：v-model 先行更新 → 调接口；成功 toast，**失败回滚开关**（client 统一 toast 错误，不双报）。
- 成功文案讲清"影响面"：
  - 开启 → `已开启：回答将参考你的记忆，系统也会在问答中提炼新记忆`
  - 关闭 → `已关闭：回答不再参考你的记忆，也不再自动提炼；已有记忆保留`

### 2.3 手动添加

- 输入框（1–200 字，strip 口径与后端校验一致，超限即时提示并禁发——对齐 ChatInput 的 1–2000 字交互口径按比例缩小）；Enter 提交（中文输入法选词回车不发送，守卫同 `frontend/src/components/chat/ChatInput.vue`）。
- 成功：清空输入框 + toast `已添加` + 回第 1 页刷新（新条目按时间降序应在首行可见，§22.3 口径）。
- **开关关闭时添加入口禁用**（按钮 + 输入框同步 disabled，tooltip：`开启记忆后可手动添加`）。禁用按钮外包 span 使 tooltip 生效（ChatInput.vue 先例）。

### 2.4 列表项信息密度

一行式表格，四列，不做卡片流（个人记忆量级小，一屏尽览优先）：

| 列 | 宽度 | 呈现 |
|----|------|------|
| 内容 | min-width，`show-overflow-tooltip` | 记忆原文，全文悬停可见 |
| 来源 | 90px | el-tag：`自动`=info / `手动`=success；tag 悬停 tooltip 解释口径——自动：`系统在问答中提炼`，手动：`你手动添加` |
| 添加时间 | 150px | `YYYY-MM-DD HH:mm` |
| 操作 | 90px | `删除` link danger（确认弹窗见 §2.6） |

DTO 无 updatedAt 时同问答对页口径：只呈现 createdAt，不虚构更新时间列。分页布局 `total, sizes, prev, pager, next`。

### 2.5 空态（区分"未积累"与"筛选无结果"）

仓库现状列表页多为单一空态文案；本页按数据是否真空区分两态（判定条件：任一筛选条件非空即"筛选无结果"分支），作为后续列表页补齐的范本：

| 场景 | 文案 | 引导 |
|------|------|------|
| 未积累（无筛选生效且 total=0） | `还没有记忆（问答中提炼或手动添加后会出现在这里）` | 按钮 `手动添加一条` → 聚焦添加输入框（开关关闭时不渲染该按钮，避免引导进死胡同） |
| 筛选无结果 | `没有匹配筛选条件的记忆，试试更换关键字` | 按钮 `清除筛选` → 重置并刷新 |

均为 el-empty + `:image-size="60"`（§8.5 空态带引导口径）。

### 2.6 删除确认：统一 ElMessageBox

- 交互：`ElMessageBox.confirm('删除后，回答将不再参考这条记忆，确认删除？', '删除记忆', { type: 'warning', confirmButtonText: '删除', cancelButtonText: '取消' })`，`.catch(() => 'cancel')` 归取消——完全对齐 `frontend/src/views/DocumentsView.vue` 的删除口径。
- 文案面向员工不出现"软删"等内部术语（用户页口径；管理员域才可写技术细节，对照 DocumentsView 的"软删保留审计"）。
- **为何不用 el-popconfirm**：知识库组兄弟页已统一 ElMessageBox.confirm（弹窗式、有标题、可承载完整后果说明）；问答对/用户管理页尚存 el-popconfirm 属历史实现，不作为新页范式，后续统一时反向收敛。
- 成功后：toast `已删除`；当前页删空回退一页（§22.3）。

### 2.7 关闭开关后的界面反馈

关闭不是"清空"，界面必须传达**冻结而非删除**：

1. 开关行常驻说明本身已写明"已有记忆保留、不自动删除"（§2.1）。
2. 关闭瞬间开关行下方出现一条可关闭的 `el-alert`（type=info）：`记忆功能已关闭：回答不再参考你的记忆，系统不再自动提炼；列表仅供查看与清理，开启后恢复。`
3. 联动禁用：添加入口禁用（§2.3）；筛选/删除保持可用（用户常在关闭时顺手清理旧记忆，删除是清理动作不是使用动作）。
4. 列表数据不隐藏、不置灰降级——保留完整可读，避免"关了像数据丢了"的错觉。

### 2.8 与 ChatView 的关系与入口提示

- **主入口**：侧边菜单 `我的记忆`（全员常驻）。首期不在 ChatView 内加常驻控件——记忆是低频管理动作，常驻入口会加重问答页信息密度。
- **场景提示（依赖后端契约，开放问题 O-1）**：系统自动提炼记忆时，若回答事件流可下发"已记住"信号，则在该条 assistant 气泡 meta 区追加灰色小字 `已记住一条记忆`，点击跳转 `/memory`（呈现口径对齐"来自缓存"小字，不弹窗打断对话）。后端首期不下发则不做，仅保留菜单入口 + 帮助文案。
- **帮助同步**：`frontend/src/help/employee.ts` 增加一节"我的记忆"（记忆从哪来、怎么关、关闭影响什么），与手册同步修订。

## 3. 模板生成（TemplateGenView，AG-UI 时间线）

### 3.1 页面结构与配置区

```
┌─ 知识库·模板生成 ──────────────────────────────────────────────┐
│ [来源文档▾] [目标部门▾] [生成数量 N] [开始生成]      [状态:空闲]   │
│───────────────────────┬───────────────────────────────────────│
│ 运行时间线（左，≈40%）  │ 草稿预览（右，流式追加）                  │
│ ● 已提交生成任务…       │ ┌ 草稿 1 ──────────────┐               │
│ ● 步骤：解析文档 ✓ 12s  │ │ 问题：…（流式出字）    │               │
│   ├ 工具：检索文档 ✓ 3s │ │ 答案：…               │               │
│ ● 步骤：规划要点 ● 8s   │ └──────────────────────┘               │
│   └ 工具：抽取要点 ● …  │ ┌ 草稿 2 ──────────────┐               │
│ ● 步骤：生成草稿 ○      │ │ …                     │               │
│ ● 子任务：质检 ○        │ └──────────────────────┘               │
└───────────────────────┴───────────────────────────────────────┘
```

- 配置区单行（对齐筛选行范式）：来源文档（选择库内"就绪"状态文档）、目标部门、生成数量；`开始生成` 主按钮。
- 主体两栏：左=运行时间线，右=草稿预览；运行结束后下方出现汇总条（§3.4）。
- 页面**不设**传统筛选/分页列表——本页是"单次运行工作台"，历史运行记录不做（开放问题 O-3）。

### 3.2 运行过程时间线（AG-UI 事件 → 呈现映射）

时间线用 el-timeline（步骤数运行期不可知，不用定长 el-steps），三级层级：

| 层级 | AG-UI 事件 | 呈现 |
|------|-----------|------|
| 0 运行 | `RUN_STARTED` / `RUN_FINISHED` / `RUN_ERROR` | 运行本身即本页一次"生成任务"，不占节点；其状态体现在页面级状态条与汇总条 |
| 1 步骤 | `STEP_STARTED` / `STEP_FINISHED` | 一级节点：`步骤：<名称>`；进行中=loading 图标 + 实时已耗时（对齐 chat 等待提示的"已等待 N 秒"口径）；完成=✓ + 耗时 |
| 2 工具 | `TOOL_CALL_START` / `TOOL_CALL_ARGS` / `TOOL_CALL_END` | 二级缩进节点：`工具：<工具名>`；ARGS 以等宽小字**默认折叠**（可展开，参数可能很大）；END 后打勾 + 耗时 |
| 2 子任务 | 子代理活动 | 聚合为一个二级"子任务"节点，其内部 STEP/TOOL 事件归入其下三级；分组依据（嵌套 runId 或 CUSTOM 事件）以 `agent-evolution.md` 契约为准（开放问题 O-2） |
| 文本 | `TEXT_MESSAGE_START/CONTENT/END` | 不进时间线，全部路由到右侧草稿预览（§3.3） |

事件应用规则完全对齐 `frontend/src/composables/useChatStream.ts` 的 `applyEvent` 模式：事件按到达顺序增量应用、驱动渲染；**未知事件名忽略不判错**（T8 评审清单②口径），心跳/未来扩展因此天然兼容。

提交后 `RUN_STARTED` 到达前呈现 0 号伪节点 `已提交生成任务…`（loading），防止开流窗口全白（对齐 chat 页 2026-10-06 等待提示修复的教训）。

### 3.3 流式草稿预览

- 每张草稿卡片对应一条 `TEXT_MESSAGE_*` 消息流：START 建卡（骨架），CONTENT 增量填充，END 定稿；卡片头显示 `草稿 N`。
- 自动滚动跟随到底（对齐 ChatView `scrollBottom`）；增强项：用户向上滚动即暂停跟随、出现 `回到最新` 浮动链接（对照 ChatView 引用面板收起/恢复的浮层做法），首期可不做但不得倒退为强制滚底。
- 流式期草稿卡片**只读**（不可编辑/删除）——草稿尚未定型，编辑动作一律去审核页做，避免两处编辑态打架。
- 内容为 LLM 生成文本，按不可信数据处理：仅渲染纯文本，不解析 HTML/Markdown 标签注入（对齐 §17.5 `<data>` 包裹的后端约束在前端的体现：前端同样不 rich-render 未审核内容）。

### 3.4 完成态与审核入口

`RUN_FINISHED` 后：

1. 两栏下方出现汇总条（对照 ServicesHealthPanel 的 overall alert）：`el-alert type=success`，标题 `生成完成：共 N 条草稿，耗时 X`，描述含 token 用量（口径同 chat done 事件）。
2. 主按钮 **`去审核`** → 跳转问答对管理页并携带批次参数（`/kb/qa-pairs?batch=<runId>`，问答对管理页需支持该 query 预填筛选——依赖草稿/批次数据模型，见 `agent-evolution.md`）。
3. 次按钮 `再生成一批`：重置配置区为上一次参数，时间线折叠为可展开摘要（`展开查看完整过程`），预览区保留至上次内容被新运行覆盖前。
4. 离开页面时若运行已结束，无拦截；运行中离开有确认（§3.6）。

### 3.5 失败 / 中断态与重试

| 场景 | 呈现 | 重试语义 |
|------|------|---------|
| `RUN_ERROR`（服务端失败） | 对应步骤节点标红 + `el-alert type=error` 展示**脱敏**错误文案（后端已脱敏，前端原样呈现，不再透传技术栈信息）；已生成草稿卡片保留 | `重试` 按钮：发起一次**新运行**（新时间线组），旧失败时间线折叠保留可查；文案 `生成失败，可重试`（对齐 chat 失败口径） |
| 用户主动停止 | 运行中常驻 `停止` 按钮（位置对齐 ChatInput：输入区旁 plain warning 按钮）；停止后节点标 `已停止`，已完成草稿保留 | 停止即可重试，同上 |
| 连接停滞（后端挂死/代理断流，无任何事件） | 由前端看门狗判停（§3.6），呈现同"失败"：`生成长时间无响应，已停止等待` | retryable=true，可重试 |
| 开流前错误（参数/鉴权/限额） | 直接进失败态，不建时间线 | 业务性拒绝（如文档未就绪）重试无意义→ retryable=false 且提示先修配置；网络/系统类 retryable=true（口径同 useChatStream 的 `NON_RETRYABLE_PRESTREAM_CODES`） |

重试始终是"新运行"，不做断点续跑——草稿按批次整体进审核，半批续跑会让批次口径混乱。

### 3.6 生成中输入锁定策略 + 心跳/超时建议（M25 看门狗议题）

**锁定策略**（对照 `useChatStream` 的 streaming 锁定 + `ChatInput.vue`）：

- 运行中：`开始生成` 按钮禁用（tooltip `生成进行中，请稍候`）、配置区各控件整体 disabled（运行中改参数无意义且易误操作）、`停止` 按钮出现。
- 一机一流：页面同一时刻仅允许一个运行（与 chat 全局串行同口径）；运行中切走再回来，运行状态随组件重建而丢失——首期接受（运行记录不持久化，开放问题 O-3），但**离开运行中页面需二次确认**：`离开将不再看到运行过程，已生成的草稿不受影响。确认离开？`（ElMessageBox，同 §2.6 交互口径）。

**心跳 / 超时建议（本页必须内建，且回灌 M25 议题）**：

现状事实：`useChatStream` 对未知事件一律忽略、`api/sse.ts` 对 SSE 注释帧整块跳过、前端**没有任何"流停滞"看门狗**——后端挂死不吐字节时前端将无限转圈（此即 M25 议题的病灶）。模板生成单次运行可达分钟级（对照解析 300s 超时口径），照搬 chat 60s 不成立，必须显式设计：

1. **服务端心跳**：AG-UI 流内周期下发心跳（任选其一，向后兼容均成立）——SSE 注释帧 `: keep-alive`（`parseSseFrames` 现成跳过），或自定义 `heartbeat` 事件（`useChatStream` 先例：未知事件忽略不判错）。**间隔 15s**。
2. **客户端看门狗**：收到任意事件（含心跳、STEP/TOOL 事件本身即活性信号）重置计时器；**超过 45s（3 个心跳周期）无任何事件 → 主动 abort**，进 §3.5 "连接停滞"失败态（retryable=true）。计时器与 AbortController 同生命周期，终态即拆。
3. **总时长兜底**：单次运行前端硬上限 **300s**（对齐解析超时口径），到点强判失败，文案区分于停滞：`生成超时（超过 5 分钟），可重试`。
4. **回灌 M25**：本页将"事件驱动 + 心跳喂狗 + 阈值判停"沉淀为可复用模式（建议抽 `useAgentRun` composable 或反哺 `useChatStream`）；chat 流（60s 口径）是否同步补看门狗及阈值取值，登记 M25 议题另行评审，本文不代决。

## 4. 通用规范

### 4.1 加载 / 错误 / 空 三态（ui-spec §8.4 / §8.5）

| 态 | 口径 |
|----|------|
| 加载 | 列表区 `v-loading`；开关初值未就绪时禁用而非隐藏；时间线运行态自身即加载态（loading 图标 + 已耗时），不叠加整页 loading |
| 错误 | 页内 `el-alert type=error` 呈现（对齐 ServicesHealthPanel 的 loadErr 模式）+ `重试` 按钮；toast 只做操作即时反馈，**不作为列表加载失败的唯一出口**（刷走就没了）。错误文案一律用后端脱敏消息，前端不自行拼技术细节 |
| 空 | MemoryView 双空态见 §2.5；模板生成页初始态（未发起运行）为引导空态：`选择文档后点"开始生成"，运行过程与草稿将在这里呈现` |

### 4.2 可访问性

- 状态不唯颜色：成功/失败均有文字标题（alert title）；时间线节点进行中 = 图标 + `进行中` 文字 + 耗时，色弱可辨。
- el-switch 配 `aria-label="记忆功能开关"`；禁用按钮的 tooltip 外包 span（键盘用户同样可得提示）。
- 运行状态摘要处设 `aria-live="polite"`（播报 `生成完成，共 N 条草稿` 等），草稿流式区**不设** live region（逐 token 播报不可用）。
- 键盘：Enter 提交（添加输入框，含输入法守卫）；ElMessageBox 默认聚焦确认按钮、Esc 取消；删除为可聚焦 link button，无纯图标按钮（因此无 tooltip-only 控件）。

### 4.3 文案语气与术语（对齐 `docs/user-guide.md`）

- 术语统一且不引入同义替代：**记忆、草稿、模板、生成、审核、来源文档**；界面上不说"个性化画像/抽取/RUN"等内部词（AG-UI 事件名只出现在本文与代码，不出现于 UI 文案）。
- 用"你"不用"您"（手册与现有气泡文案口径）。
- 按钮两字动词开头：`添加 / 删除 / 重试 / 停止 / 刷新`；跳转类 `去审核`。
- 成功提示 = 结果 + 影响（`已关闭：回答不再参考你的记忆…`）；失败提示 = 现状 + 下一步（`生成失败，可重试`）；确认弹窗写清不可逆后果再问（§2.6）。
- 上线时两页文案并入手册：MemoryView 进第一篇（员工篇），模板生成进第二篇"知识库"章，并同步 `frontend/src/help/`。
