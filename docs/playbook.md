## 1. 新人第一天（导师陪同）

**上午 · 环境**（目标：全绿；卡住超 1 小时找导师，别自己修环境）：

```bash
git clone <仓库地址> && cd RagDemo
make install            # 建 .venv 并安装 -e ".[dev]"
make test               # 全量 pytest 全绿 = 环境正确
make up                 # 本地 compose（pg 等）
cp .env.example .env    # 向导师领本地密钥；.env 永不入库
make lint               # ruff check + format 双绿
```

**下午 · 只读三样**（顺序固定，共约 2 小时）：

1. [AGENTS.md](../AGENTS.md)——七项红线逐条能复述；
2. 本手册通读一遍；
3. §3 的真实案例精读（本仓库真实缺陷的完整走法）。

**出师检查**：能说出红线任意五项；能答出"一个 MR 要过哪两道关"（§4.3 分级评审 + CI 全绿）。之后首卡固定领一个"好啃 bug"（§3），走通全流程即出师。

## 2. 领卡干活

### 2.1 开工：启动 AI 会话（一会话一卡）

新会话原样粘贴：

```text
你是本项目的开发工程师。本会话只处理任务卡 #{{卡号}}，禁止跨卡操作、
禁止改动触达声明之外的文件。

任务卡全文：
{{粘贴任务卡（模板见 §9.1）}}

请按顺序执行，每完成一步停下等我确认：
1. 复述验收标准，指出你不确定或有歧义的点；
2. 只读探索触达文件，给出"现状 → 改法"清单（精确到文件与行号）；
3. 产出实现计划：分支名（feat/<模块>-<简述>）、改动文件清单、测试计划、
   文档同步项；计划不写代码；
4. 我回复"确认计划"后才开始写码。

约束：遵守 AGENTS.md 全部红线；需要越出触达声明时停下说明，等我裁决。
```

**你要做的事**（每步 30 秒）：核对复述与卡一致，歧义当场裁决记回卡评论；抽查两条"现状"是否属实（编造现状=立即纠偏）；核对改动清单 ⊆ 卡上触达声明。

### 2.2 写码：TDD 三步循环（`rag/` 与 `services/` 强制）

- **【红】**先写失败测试（用例标题用中文描述行为），跑 `make test-unit`——失败原因必须是"功能未实现"，语法错的红不算；
- **【绿】**最小实现到同一命令全绿；实现只动计划内文件；
- **【证】**写库测试带**读回断言**（SELECT 验证落库）；断言精确到状态码与关键字段，禁止 `A or B` 宽松断言；最后 `make lint`。

两个特殊情况：测试没红直接绿 = 没有新行为要加，**停**，回卡确认是不是重复卡；涉 `rag/` 或提示词的改动，MR 必附评测对比（§4.2）。

### 2.3 提交前检查表（12 项一张表，逐项打勾再推 MR）

| # | 检查 | # | 检查 |
|---|---|---|---|
| 1 | 部门查询带过滤，按 ID 访问校验归属 | 7 | 审计留痕 + 错误脱敏 |
| 2 | SQL 全参数绑定，无 f-string 拼接 | 8 | 界面文案三源联动（见 2.4） |
| 3 | 知识不足拒答路径未被破坏 | 9 | AI 产出：引用的 API 全部真实存在 |
| 4 | 密钥零泄漏（代码/日志/响应/.env） | 10 | AI 产出：未越层直查其他模块的表 |
| 5 | 上传白名单/落盘/上限未放松 | 11 | AI 产出：测试断言独立于实现（非迁就） |
| 6 | LLM：max_tokens clamp、user role、`<data>` 包裹 | 12 | AI 产出：守账数字未手改（见 2.4） |

### 2.4 两条同步铁律

- **文案三源联动**：改任何用户可见文案 → `frontend/src/` 业务代码 + `frontend/src/help/` + `docs/user-guide.md` 三处一起改，改完 `grep` 旧文案确认零残留；
- **守账数字不手写**：api.md 端点数等以 `tests/unit/test_api_contract.py` 对账为准，人和 AI 都不许手写数字。

## 3. 修 bug

新会话原样粘贴：

```text
本会话只修一个 bug，禁止顺手改其他任何东西。

Bug 现象：{{一句话}}
复现路径：{{最小复现步骤，精确到命令/操作}}
已知根因：{{有就写；没有写"未知，请先定位"}}

流程（每步停下贴输出）：
1.【复现】先写复现测试，构造最小输入；红不起来不许动实现，回来告诉我原因。
2.【定位】根因链：文件:行 → 为什么错 → 为什么此前没被测试拦住。
3.【修复】最小侵入；拒绝 try/except 掩盖（那是把缺陷变静默）。
4.【回归】复现测试转绿后跑 make test 全量，确认零回归；测试永久保留。
产出：fix/{{短名}} 分支 + 复现测试 + 修复 + MR。
```

**真实案例 3 分钟**（本仓库真实缺陷）：W5 部署验收发现部分 docx 解析失败。根因：Xstudio/WPS 生成的文件引用 styles.xml 未定义样式，python-docx 返回 `style=None`，取 `.name` 抛错。守卫已落 `app/rag/parser.py:82`（判空走默认值），但**复现测试长期缺失**（账本 F-3 带走项）——守卫没了测试锁，下次重构随时改坏。

补测的证红技巧（修复已存在时怎么拿到"红"）：在修复前的历史 commit 上跑新测试——

```bash
git log --oneline -- app/rag/parser.py          # ① 找守卫落地前的 commit
git worktree add ../RagDemo-red <旧commit>       # ② 独立工作树，不脏当前树
# ③ 把新测试与夹具改动拷入 ../RagDemo-red 对应路径
(cd ../RagDemo-red && make install && make test-unit)   # ④ 期望：红（AttributeError）
git worktree remove ../RagDemo-red               # ⑤ 回主树跑新测试 → 绿，合入
```

禁止在主树注释守卫"反向证红"——忘恢复就是真事故。

## 4. 提交与评审

### 4.1 分支与提交

`feat/<模块>-<简述>` / `fix/<问题>`；一个提交一件事；分支存活 ≤3 天（超期合入或拆卡）。提交用显式路径 `git add <文件>`，**禁止 `git add -A`**——工作树常有他人并行会话的在途文件（§8）。

### 4.2 MR 必含要素（缺一项评审人直接打回）

① 任务卡号；② 变更内容三句内；③ 自测记录（命令 + 结果原文）；④ §2.3 检查表 12 项勾选；⑤ 高危声明（触达 §8 高危文件 → 列文件 + owner 复审人）；⑥ 评测对比（`rag/`/提示词变更必附：main 基线 vs 本分支两列表，**拒答类指标只许持平或升，降 = 停下人裁**）；⑦ 界面截图（界面变更）。

### 4.3 分级评审

| 变更类型 | 批准要求 |
|---|---|
| 普通 | 1 人批准 + CI 全绿 |
| auth / 数据库迁移 / standards.md / 安全相关 | 2 人批准且含模块 owner |

SLA：工作日 **4 小时首响、24 小时完成**；超时 MR 里 @owner，再超时升级 PDT 经理。意见必须落 MR 评论，禁止口头评审。

### 4.4 评审人怎么审（按序过）

红线 12 项表（§2.3）→ 分层纪律（`api→services→rag→core→db` 单向，跨模块取数走 service 函数，api 层无裸 SQL）→ 测试质量（红在绿前？断言精确？读回断言？）→ 文档同步（§2.4）→ 触达范围 ⊆ 卡声明。

意见三要素：`[Critical|Important|Minor] 文件:行 + diff 原文证据 + 可执行建议`。"建议优化下"不是意见。**批准必须人工**——AI 可生成预审意见供参考，但不构成批准。

## 5. 数据库迁移

**五约束**：仅追加、永不改历史脚本；新增列可空或带 `server_default`；CHECK/FK 一律具名；每列中文注释且 ORM `comment` 与迁移**逐字一致**（autogenerate 零差异守卫依赖）；up/down 成对。

**三红线自检**（写进 MR）：① 非空列必带默认值（否则回滚镜像后 INSERT 失败）；② 枚举 CHECK 加新值 = 破坏性迁移，必须配降级脚本；③ 换 embedding 模型 = 回滚须重建向量索引（能跑但检索静默劣化），发布说明声明。

**验证命令**（输出逐条贴 MR）：

```bash
alembic upgrade head
alembic downgrade -1      # 可回滚实证
alembic upgrade head
```

**撞 head**（多人并行必遇，规则：后合入者负责重排）：

```bash
git fetch origin main && git rebase origin/main
# 把你迁移文件的 down_revision 改指新 head（历史脚本零触碰）
alembic upgrade head && make test-api
git push --force-with-lease
```

数据回填逻辑写**服务层适配器**（先例：`app/services/doc_type.py` 的 `chunks_detect_inputs`），迁移只管结构。

## 6. 发布（双人：发布人 + 值守观察人）

**前置**：非高峰窗口；试点部门已通知；staging 冒烟过；`deploy/releases.md` 已记录本镜像 digest 与**回滚目标**（上一 digest——必须发布前就写，不能回滚时现找）。

**冒烟五项**（发布后版本上再复抽一轮）：登录 / 上传解析 / 问答带引用 / 点踩 / 部门隔离抽查。

**值守**：30 分钟错误日志（重点 5xx、LLM/检索超时）+ 复抽冒烟 + 登记 releases.md；两人都在场。

**回滚决策树**（判断条件唯一，禁止现场发挥）：

```text
发现缺陷
├─ 破坏性迁移已执行且旧镜像跑不了？ → 跑降级脚本回迁，再回退镜像
├─ 否 → 默认：镜像回退到上一 digest → 冒烟 → 30 分钟值守 → 缺陷转 fix 卡（§3）
└─ 前滚仅当三条全满足：根因明确 + 修复现成 + 修复时长 < 回滚时长
```

## 7. 迭代收口（当值轮值）

节奏：**2 周一迭代**；计划会 30 分钟 = 回顾 5' → 看板过卡 10' → 拆卡领卡 + 高危文件认领 10' → 风险与轮值 5'。任务**纵切**优先：一张卡 = 一个可独立验收的用户价值（含测试与文档同步义务）。

收口四件套（按序，缺一不算收口）：

1. **全量回归**：`make test` + 前端四门（`npm run lint` / `type` / `test` / `build`，在 `frontend/` 下）——红了先修再收口；
2. **打 tag**：`vX.Y.Z`（语义化版本，§13.1）；
3. **staging 部署**：main 最新 tag 产物 + 冒烟；
4. **迭代报告**（模板 §9.4）归 `docs/archive/`（文件名带日期前缀）。**偏离 SOP 的事必须写进"偏离记录"**——不记录 = 违规；记录了 = 流程改进的原料，回顾会逐条过，该改手册的当场改。

## 8. AI 协作铁律

1. **一会话一卡**；长任务新起会话重载上下文，优于续用污染会话；
2. **密钥、真实用户数据、生产库内容禁止贴入任何 AI 会话**（内部知识文档除外——那是产品本职）；测试一律用 fixtures 与种子数据；
3. **共享高危文件**（`AGENTS.md`、`docs/standards.md`、`alembic/versions/`、`.github/workflows/`、`docker-compose*.yml`、`Makefile`、docs/ 活文档）触达须在卡与 MR 声明，合入前模块 owner 复审；
4. 提交**显式路径 add，禁止 `-A`**；
5. AI 预审可参考，**批准必须人工**。
