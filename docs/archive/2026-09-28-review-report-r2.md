## 三、P1 修复摘要（35 项，按主题归并，全部修复）

**预检两段式（本轮最重要，3 个角色交叉发现同一矛盾）**：simhash/敏感/乱码依赖解析文本却画在解析前——重构 flows F1 为两段式：**同步段**（毫秒级）=三重白名单+SHA-256 精确查重；**异步段**（解析后）=质量红线→清洗→乱码/敏感（含 OCR 文本）/simhash；standards §10.8 同步改写；近重复/待脱敏文档 `is_active=false 待确认`，确认后激活（补齐 F-1002 状态落点）。

**高安全（M10 新攻击面封堵）**：zip 条目逐条过白名单与 ≤50MB、嵌套 zip 拒收、解压上限递归累计边解压边计数（§6.3）；文件名自动填元数据的注入面封堵——部门限枚举+限上传人管辖、日期格式白名单、责任人=上传人兜底、命名不符"待补"不入库（F-1007/1008）；模型工件供应链闭环——构建期下载同样强制 hash、基准从可信外网官方源双人复核、URL 钉 revision commit、compose 以 digest 引用（§12.8/设计 §6.3）；批量导入并发=1 共用餐票防解析通道被打满。

**口径与一致性**：查重算法统一 SHA-256（features/flows/db/test 四处）；content_hash 改部分唯一索引（`WHERE deleted_at IS NULL`，软删可重传）；chunks.dup_of 补 `ON DELETE SET NULL` 且折叠改为查询内存态、dup_of 仅离线批注；qa_pairs 补 embedding_model 列（模型升级判别）；scaling-plan §四 B 行 messages 分区残留清除。

**产品与计划**：M10 工作量修正为 8-12 人日 + 裁剪顺序（F-1011→F-1010→F-1012 可降级，F-1001~1006/1009 必做）；里程碑对齐（预检两段分落 W1/W3，zip/元数据建议 W4，缺口报告/统计 W5 可裁剪）；F-1004 通知=MVP 清单+审计（不做邮件）；F-1006 脱敏口径定义（文本层打码+重跑扫描+原文件受限归档）+验收量化召回 100%；F-1008 验收量化 ≥18/20；CPU rerank 1-3s 与检索 <1.5s 矛盾补 MVP 触发线（实测超预算提前升 GPU 或缩输入）；设计 §12 补 3 行新风险（预检误拦/扫描成本复用同批结果/批量导入占道）；brief 待办表补模型选型（W2 前）、RAGFlow 决策（W3 前）、评判人力（W3 前）。

**界面与原型**：M10 必须可视的三处补进原型（上传对话框自动预检结果、健康度概览条、到期日期字段）；断流演示（输入含"断流"触发 error 分支+重试按钮）；阈值扫描/知识缺口卡登记 deviations 豁免（文字规格足够）；用户可见文案清除功能编号残留；解锁确认文案统一；空输入 tooltip；citations 字段名对齐 §3.6（refType/titlePath）；删除保持当前页（§22.3）；done 事件 durationMs 演示；点踩写审计；预检三态机定义（绿/黄/红）写入 ui-spec；健康度红黄触发条件写入；阈值扫描实现约束与推荐规则写入；术语表增补 6 词（预检/健康度/零召回/知识缺口/阈值扫描/到期日期）。
